# Codex Edits Outside `platform/linux`

This file documents the non-Linux-file edits made while bringing the Linux
target closer to a working baseline. The Linux-specific implementation files
under `library/platform/linux/` are intentionally not listed here.

## Compiler Driver

### `driver/doletc_driver.dlt`

- Skipped `dsl_runtime` in `extract_extern_libs`.

  Reason: Linux declares syscall helpers with `extern lib "dsl_runtime"`, but
  those symbols are implemented by `platform/linux/resources/runtime_helpers.o`
  and linked explicitly through `platform.conf`. Without this exception, the
  driver also emits `-ldsl_runtime`, causing `ld.lld` to fail because no
  separate `libdsl_runtime` library exists.

- Added a guard before appending the platform stack flag.

  Reason: not every platform has a valid stack-size linker flag. Windows uses a
  real stack flag, but Linux `ld.lld` does not accept the previous
  `-z stacksize=...` form. The driver now only appends the stack flag when the
  platform config provides one.

### `build/pipeline_build.dlt`

- Regenerated by `build.bat`.

  Reason: this file is the concatenated compiler source used by the bootstrap
  build. It changed automatically because `driver/doletc_driver.dlt` changed.

### `bin/doletc.exe`

- Rebuilt by `build.bat`.

  Reason: the driver change must be present in the actual compiler binary, or
  `--target linux` would still use the old linker behavior.

## Standard Library / Platform Split

### `library/std/mod.dlt`

- Added `load std/time` and exported `Time`.

  Reason: `std/time.dlt` already exists as a portable facade, but it was not
  loaded by `import std`. Loading it makes `Time.now_ms()`, `Time.sleep_ms()`,
  and related helpers available consistently.

- Changed thread and mutex loading to:

  ```dolet
  load platform/{platform}/thread
  load platform/{platform}/mutex
  ```

  Reason: `Thread` and `Mutex` are OS-backed primitives. Keeping their concrete
  implementations directly in `std/` made Linux pull Windows-only APIs. Loading
  them from the active platform keeps the public API stable while allowing each
  OS to provide its own implementation.

### `library/std/thread.dlt`

- Replaced the old Win32 implementation with a small facade note.

  Reason: `std` should not own a Windows-specific thread implementation. The
  real implementation now lives under `platform/windows/thread.dlt`, and Linux
  can provide its own implementation under `platform/linux/thread.dlt`.

### `library/std/mutex.dlt`

- Replaced the old Win32 implementation with a small facade note.

  Reason: same as `Thread`: `Mutex` must be platform-owned because Windows uses
  `CRITICAL_SECTION`, while Linux should eventually use a futex-backed mutex.

### `library/platform/windows/thread.dlt`

- Added the previous Windows `Thread` implementation here.

  Reason: this preserves the existing Windows behavior after moving thread
  ownership out of `std/`.

### `library/platform/windows/mutex.dlt`

- Added the previous Windows `Mutex` implementation here.

  Reason: this preserves the existing Windows `CRITICAL_SECTION` behavior after
  moving mutex ownership out of `std/`.

### `library/platform/windows/mod.dlt`

- Added `load platform/windows/time`.

  Reason: after `std/mod.dlt` started loading `std/time`, the Windows platform
  layer must load `TimeOps` before the standard facade uses it.

## Package Platform Backend Split

### `library/mod.dlt`

- Added registry entries for raw Windows bindings such as
  `sys.windows.win32.user32`, `sys.windows.win32.gdi32`,
  `sys.windows.win32.xinput`, `sys.windows.win32.winsock`, and
  `sys.windows.win32.vulkan_surface`.

  Reason: packages need a stable import name for OS bindings without depending
  on physical file paths.

### `library/platform/windows/kernel32.dlt`

- Added `GetModuleHandleA`, `GetLastError`, and `SetLastError`.

  Reason: `kernel32` is already part of the Windows platform runtime, so window
  backends should use the platform binding instead of carrying a duplicate
  package-local `kernel32.dlt`.

### `library/platform/windows/win32/*`

- Added raw Win32/XInput/Winsock binding files moved out of packages.

  Reason: raw OS declarations belong to `library/platform/<os>`, while packages
  should only own their public API and package-specific backend logic.

### `packages/window`

- Changed `mod.dlt` to load `window/platform/{platform}/...`.
- Kept only target-neutral public constants in `window/constants.dlt`.
- Moved the Windows backend files under `window/platform/windows`.

  Reason: `window` should expose one API while each OS owns its own backend.

### `packages/input`

- Changed `mod.dlt` to load `input/platform/{platform}/...`.
- Moved Win32 keyboard/mouse and XInput-backed gamepad code under
  `input/platform/windows`.

  Reason: input backends are platform-specific, but public input functions stay
  package-level.

### `packages/net`

- Changed `mod.dlt` to load `net/platform/{platform}/tcp`.
- Moved Winsock-backed TCP code under `net/platform/windows`.

  Reason: socket implementation differs per OS. The package root should remain
  a stable public entry point.

### `packages/frog`

- Changed Frog input and Vulkan context loading to platform-specific paths:

  ```dolet
  load frog/core/platform/{platform}/time
  load frog/core/platform/{platform}/input
  load frog/render/platform/{platform}/gpu_vulkan_context
  ```

  Reason: these files were Windows-specific. The public Frog API stays stable,
  but OS-specific input and native Vulkan surface setup now live under the
  active platform backend.

- Changed `frog/core/time.dlt` to call platform hooks
  `frog_time_frequency()` and `frog_time_now_ticks()`.

  Reason: the core timer directly called Win32 `QueryPerformanceCounter`,
  which broke `--target linux`. Windows still uses QPC through its backend;
  Linux uses `clock_gettime` through `TimeOps.time_now_ns()`.

### `packages/vulkan`

- Changed `mod.dlt` to load `vulkan/platform/{platform}/vulkan`.
- Moved the existing Windows Vulkan declarations to
  `vulkan/platform/windows/vulkan.dlt`.
- Added a Linux copy that uses `extern lib "vulkan"`.

  Reason: Windows links the local `dolet-vulkan-1` import library, while Linux
  should link system `libvulkan`.

## Linux Frog Backend

### `packages/window/platform/linux/*`

- Added a first X11 backend for the shared `Window` API.

  Reason: Frog needs a native window handle and an X11 `Display*` to create a
  Linux Vulkan surface. `Window.handle()` returns the X11 Window and
  `Window.hinstance()` returns the Display pointer on Linux.

### `packages/frog/core/platform/linux/*`

- Added Linux input and time backends.

  Reason: keyboard/mouse polling now uses X11, and engine time uses the Linux
  platform clock through `TimeOps`.

### `packages/frog/render/platform/linux/gpu_vulkan_context.dlt`

- Added an Xlib Vulkan context backend.

  Reason: Linux requires `VK_KHR_xlib_surface` and
  `vkCreateXlibSurfaceKHR`, while Windows requires `VK_KHR_win32_surface` and
  `vkCreateWin32SurfaceKHR`.

## Verification

- `build.bat` passed and rebuilt `bin/doletc.exe`.
- A basic Linux target compile/link passed:

  ```powershell
  .\bin\doletc.exe .tmp_linux_basic.dlt -o .tmp_linux_basic --target linux -O2
  ```

- Full Windows test suite passed:

  ```text
  105 PASS / 0 FAIL
  ```

- `import frog` compile still passes on Windows after the platform split:

  ```powershell
  .\bin\doletc.exe _codex_frog_probe.dlt -o build\codex_frog_probe_windows.exe -O3
  ```

- `import frog --target linux` reaches the Linux linker cleanly from Windows.
  The only failure here is expected on Windows because `ld.lld` cannot find
  Linux system libraries:

  ```text
  ld.lld: error: unable to find library -lvulkan
  ld.lld: error: unable to find library -lX11
  ```

## Known Follow-Ups

- Linux `Thread.spawn` is still a placeholder until a real `clone/futex` design
  is implemented.
- Linux `Process.run_capture` / `run_output` still need pipe-based capture.
- The generated Linux ELF was compile/link verified from Windows, but runtime
  execution still needs testing inside Linux, WSL, or QEMU.
- Linux package backend for `net` is still missing.
- Linux `window` fullscreen/windowed mode currently stores mode state only; it
  does not yet switch monitor modes or EWMH fullscreen state.
- Linux `WindowSoftwareSurface.present_rgba8` is a placeholder because Frog
  currently uses Vulkan. Add an X11 image/blit path if software rendering needs
  Linux display output.
- Missing package backend files currently produce `mod.dlt: cannot load ...`
  warnings and may later fall into a less helpful codegen error. The compiler
  should eventually hard-fail missing backend loads early.
- `import net` currently resolves to `library/std/net` before `packages/net`,
  so the old package net backend is migrated but still shadowed by the std
  registry entry.
